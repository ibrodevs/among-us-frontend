# ТЗ №1 — Ибро: Frontend, главное меню, идентификация и лобби

**Ветка:** `feature/ibro-lobby-ui`  
**Репозиторий:** `ibrodevs/among-us-frontend`  
**Ответственность:** пользовательский путь от открытия сайта до входа в активную игру. Байэл не должен изменять этот модуль без согласования.

## 1. Результат работы
Пользователь с компьютера или телефона открывает сайт, вводит никнейм, создаёт приватную комнату либо присоединяется по коду, видит участников, копирует приглашение, может выйти; хост запускает матч, когда участников ≥4, и все попадают в игровой экран. Никакого фейкового старта матча. Интерфейс должен быть современным, адаптивным и полностью на русском (архитектура готова к i18n позже).

## 2. Зона владения
- `src/app/page.tsx` — главная страница.
- `src/app/room/[code]/page.tsx` — лобби.
- `src/components/lobby/**` — карточки, формы, список игроков, индикаторы статусов, кнопки.
- `src/lib/api.ts`, `src/lib/guest.ts`, `src/lib/config.ts` — REST, гостевая сессия и переменные окружения.
- `src/lib/types.ts` — координировать изменения с Байэлом, не ломать существующие поля.
- `src/app/globals.css` — только общие токены и базовые стили. Байэл собственные стили изолирует внутри game-модуля.
**Не изменять:** `src/app/game/**`, `src/features/game/**`, `src/components/game/**`.

## 3. Главный экран (UX/UI)
1. Брендинг Crew Mission и original sci-fi визуальный стиль: глубокий тёмный фон, контрастные карточки, свечение, читаемые шрифты; не копировать официальные ассеты Among Us.
2. Поле имени 2–16 символов, trim, понятная ошибка и фокус при ошибке; кнопки «Создать комнату» и «Войти по коду».
3. Поле кода ровно 6 символов, uppercase, удаление пробелов; поддержка вставки из буфера.
4. Состояния загрузки, недоступности backend, неправильного кода, полного лобби, уже запущенного матча, просроченного guest-token. Не выводить технические stack traces.
5. Работа клавиатурой и экранным диктором: метки у инпутов, видимый focus, Enter для отправки форм, aria-live для статусов.
6. Адаптивность от 360 px до широкого десктопа, контраст WCAG AA насколько возможно, без горизонтальной прокрутки.
7. Отключать двойные запросы при loading, не вызывать несколько `createRoom` от двойного клика.

## 4. Гостевая сессия
1. При создании/входе выполнить `POST /api/v1/guests/`, сохранить только `player_id, nickname, token` для текущего браузера; сессия живёт 24 часа.
2. Существующая сессия с тем же никнеймом может использоваться повторно. Изменение никнейма создаёт новую guest identity.
3. После 401 истёкший токен не пытаться использовать бесконечно. Сообщить пользователю, предложить новую сессию и повторный вход в комнату по коду. Очистка устаревшей записи обязательна.
4. Токен передавать только через заголовок `Authorization: Guest <token>`; никогда через URL, аналитику или клиентские логи. На сайте предусмотреть заметку, что это гостевой игровой идентификатор, а не учётная запись.
5. Вызовы `gameApi` строго типизировать, обрабатывать non-2xx JSON error `detail`, AbortController при уходе со страницы по необходимости.

## 5. Создание комнаты
1. `POST /api/v1/rooms/` с `{"max_players":4..10}` (по умолчанию 10).
2. После 201 перейти на `/room/{code}`. В ответе от сервера должны быть статус waiting, хост и список участников. Не генерировать код на клиенте.
3. Валидация: полный диапазон 4–10. Показывать сколько слотов доступно. При ошибке оставаться на форме с сохранением введённого.
4. Приватная комната определяется серверным кодом, не показывать незавершённую "комнату" при API failure.

## 6. Вход в комнату
1. `POST /api/v1/rooms/join/` с uppercase кодом.
2. Ошибки: 404 «комната не найдена»; 409 «комната заполнена/игра уже началась/ник занят», 401 «нужно обновить гостевую сессию». Сообщения должны быть понятными.
3. Повторный join текущим игроком должен приводить в эту же комнату (идемпотентность на backend).
4. Если введена ссылка с кодом, но игрок ещё не авторизован гостем, корректно направить на ввод имени без потери кода.

## 7. Лобби
1. Отобразить код приглашения, кнопку «Скопировать код», по возможности кнопку «Скопировать ссылку» и уведомление о копировании.
2. Список игроков 1–10; для каждого: никнейм, индикатор онлайн/офлайн, иконка хоста, уникальный key по UUID.
3. Показать текущее число игроков, минимум 4, заполненность, статус и безопасный текст «Ожидаем игроков».
4. Кнопка «Начать игру» только для хоста и только при 4+ участниках. Пока API запрос выполняется, disable кнопки; не переводить UI в playing до успешного ответа сервера.
5. После ответа start или real-time event `game.started`/изменения `room.snapshot` при playing перейти на `/game/{code}`.
6. Кнопка выхода вызывает `POST /api/v1/rooms/{code}/leave/`. После 204 вернуться домой. Переназначение хоста отображается при обновлении данных.
7. На первом этапе разрешён poll GET каждые 2–3 с. После интеграции с Илияр использовать `room.snapshot` и события WebSocket, poll оставить как fallback.
8. Раздельные ошибки initial loading, refresh, leave, start. Если сервер недоступен — отображать «Переподключение…», не очищать без причины список игроков.
9. Не показывать секретные роли, задачи или внутренние игровые данные.
10. Обновление страницы в существующей гостевой сессии должно восстанавливать лобби без повторного join.

## 8. API и договорённости
Обязательные endpoint names и response fields в `docs/API-CONTRACT.md`. Нельзя изменять имена URL или JSON полей без согласования с Кутманом. Байэлу передать `GuestSession`, `Room`, `gameApi`, URL `/game/[code]` и общие цветовые токены.

## 9. Обязательные тесты / приёмка
- Валидная/невалидная длина никнейма, пробелы и Unicode.
- Создание комнаты 201, переход, отображение кода; 400 и 500 без crash.
- Вход по коду 200; неверный формат/404/409.
- Сохранение гостевой сессии после refresh; 401 просроченного токена.
- Двойной click не отправляет два POST.
- Хост и обычный участник видят разные кнопки; недостаток игроков блокирует Start.
- 4+ игрока и успешный Start ведёт на game route; ошибочный Start остаётся в лобби.
- Корректный выход и передача статуса; clipboard failure fallback.
- Адаптивность 360/768/1440 px, работа клавиатуры, читаемые ошибки.
- Нет утечки токенов через URL/console; `npm run typecheck`, `npm run lint`, `npm run build` проходят.

## 10. Этапы и definition of done
**Этап A:** качественная главная страница + guest session + доступный дизайн.  
**Этап B:** REST create/join и полноценное лобби.  
**Этап C:** синхронизация с Илияром, состояния start/reconnect, тесты и UX-polish.

Готово только после демонстрации сценария «создать → получить код → второй пользователь вошёл → отображаются оба → старт → игровой маршрут», фиксации ошибок/проверок и PR в `main` с коротким видео/скриншотами. Согласовать с Байэлом, как обработать переход game→lobby.
