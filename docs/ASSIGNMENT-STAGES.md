# Задания с доски

Рабочая версия: `among-us-frontend-main` + `among-us-backend`.

## 1. Сохранение сессии

Гостевой токен и ник сохраняются в браузере. Теперь сохраняется и код последней
комнаты с привязкой к ID гостя. На главной странице есть «Продолжить сессию»:
сервер проверяет доступ и направляет в лобби или текущий матч. Обновление страницы
и переподключение используют прежнего игрока, роль и задания с сервера.
При явном выходе сохранённая комната удаляется. Ошибка сети оставляет возможность
повторить восстановление; истёкшая сессия или удалённая комната убирают ссылку.
Гостевой токен действует 24 часа; это восстановление в том же браузере.

## 2. Готовность лобби

Каждый участник, включая хозяина, нажимает «Я готов» и может отменить готовность.
Статус виден всем через снимки лобби. Сервер разрешает старт только хозяину,
при достаточном составе и готовности всех участников. Новые участники не готовы.
Изменение настроек сбрасывает готовность; повторное сохранение без изменений — нет.

API: `PATCH /api/v1/rooms/{code}/ready/`, тело `{"is_ready": true|false}`,
авторизация `Guest`. Возвращает Room с полем `players[].is_ready`.
После старта изменение готовности возвращает 409.

Перед запуском обновлённого сервера: `python manage.py migrate`.

## 3. Одиночная прогулка

На главной странице — «Одиночная прогулка по карте», маршрут `/demo/asterion`.
Режим существовал в проекте; вход и инструкции уточнены. Сервер и другие игроки
не нужны. Есть движение, коллизии, карта M, управление WASD/стрелками и джойстик.

## 4. Минимум 7 типов заданий

В Asterion уже реализованы 20 типов. Примеры семи разных механик:

| Тип | Действие |
| --- | --- |
| `wires` | Соединить цветные кабели |
| `power_routing` | Переключить реле по схеме |
| `upload` | Удерживать передачу данных |
| `engine_calibration` | Настроить частоты и зафиксировать роторы |
| `oxygen_filters` | Очистить фильтры и включить их в нужном порядке |
| `fuel_distribution` | Распределить топливо |
| `sequence` | Повторить последовательность из памяти |

Интерфейсы: `AsterionTask.tsx`; серверные генераторы и валидаторы: `game/tasks.py`.
Сервер проверяет назначение, расстояние, решение и время выполнения. Число
типов в каталоге и число заданий одного игрока — разные параметры. По умолчанию
игрок экипажа получает 7 заданий; набор настраивает хозяин. Одиночная прогулка
предназначена для исследования; задания выполняются в сетевом матче.

## Проверка

- Frontend: `npm test`, `npm run typecheck`, `npm run lint`, `npm run build`.
- Backend: `python manage.py test`, `python manage.py makemigrations --check --dry-run`.
- `rooms.test_readiness` проверяет готовность, права, сброс и запрет раннего старта.
- `game.tests.test_v2` проверяет все 20 решений через игровую логику.
- E2E: `npm run test:e2e`; нужен полный PostgreSQL/Redis/API/worker стек.

### Результаты локальной проверки 18.11.2026

TypeScript, ESLint, 12 frontend-тестов и production build прошли. В браузере
Chrome прошли `practice.spec.ts` и `session-lobby.spec.ts` с настоящим API:
прогулка без API, пауза на карте, готовность после reload, возврат в лобби/матч
и очистка сохранённой комнаты при выходе. Для проверки API использована отдельная
SQLite-база; полный сетевой матч с worker в этом прогоне не проверялся.

Серверный набор из 106 тестов: 102 успешных, 4 пропущены по возможностям БД.
Миграции согласованы с моделями, `manage.py check` прошёл. В полном наборе
выявлены два ограничения SQLite: `test_worker_leader_session_lock_releases`
требует PostgreSQL advisory lock; конкурентный
`test_public_and_private_snapshot_share_one_database_version` получает
`database table is locked`. Эти проверки требуют PostgreSQL/Redis окружения.
