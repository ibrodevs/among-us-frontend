# ТЗ №2 — Байэл: Frontend игрового процесса и real-time UI

**Ветка:** `feature/bayel-gameplay-ui`  
**Репозиторий:** `ibrodevs/among-us-frontend`  
**Ответственность:** экран матча и все игровые элементы после перехода из лобби. REST guest/room формы принадлежат Ибро.

## 1. Конечная функциональность
Пользователь после старта видит одну оригинальную 2D-карту космической станции (логические координаты 1600×900), свой персонаж, других игроков, задачи, кнопки действий. Передвижение синхронизировано через WebSocket. Экипаж выполняет задания, предатели убивают и могут участвовать в собраниях, игроки голосуют, UI показывает серверный результат. Не доверять клиенту в определении ролей, убийств, голосов и победителя.

## 2. Зона владения
- `src/app/game/[code]/page.tsx` — page и состояния route.
- `src/features/game/**` — WebSocket hook/store, game state reducers, input, canvas, collision visuals, интерполяция, мини-игры.
- `src/components/game/**` — UI игрового экрана, HUD, модальные окна и экран результата.
- `public/game/**` — **только собственные / легально разрешённые ассеты**, оптимизированные для браузера.
Не трогать главную, лобби и REST-клиент Ибро. Для общих `src/lib/types.ts`/цветов согласовать изменения и сделать маленький отдельный PR.

## 3. Экран и структура UI
Разместить:
1. Canvas world-map или эквивалент с камерой, плитками пола, визуальными стенами, минимум 4 различимых отсека (двигатели, управление, связь, медблок), проходами и точками задач.
2. Цветные оригинальные персонажи (не копировать дизайн Among Us) с никнеймом над фигурой, подсветкой своего игрока, анимацией простоя/шага.
3. HUD: роль **только своего игрока**, статус жив/мёртв, прогресс заданий, список собственных задач, кнопку настроек/выхода, ping/connection status.
4. Контекстные кнопки `Use`, `Report`, `Kill` (только предателю), `Emergency`. Кнопки неактивны, если серверный state не позволяет действие; ошибка с сервера отображается, не предполагается успех.
5. Экраны Meeting: инициатор, таймер обсуждения, список живых, голосование/skip, ожидание остальных, итоги.
6. Финальный экран: победитель, причина победы, список игроков/ролей **после завершения**, кнопка возврата в меню.

## 4. Перемещение и отрисовка
1. Управление WASD и стрелками, диагональный вектор нормализовать; для телефонов — D-pad/виртуальный джойстик или 4 крупные кнопки.
2. Input отправляется событием `player.move` c monotonically-increasing `seq` не чаще 10–20 раз/сек; клиент рисует свой prediction, затем сверяет с server snapshots.
3. Сервер задаёт скорость и коллизии. Не отправлять свободно выбранные `x,y` как подтверждённую позицию игрока.
4. Для удалённых игроков реализовать interpolation с buffer 100–150ms; без резких телепортов при нормальном ping.
5. Мир рендерить в logical 1600×900 с масштабированием и follow-camera на телефоне; Canvas `requestAnimationFrame` + cleanup listeners на unmount.
6. Не перерисовывать весь React-tree на каждое movement event. Внутри renderer использовать refs/cache.
7. При невалидных/частичных событиях не падать; валидация event discriminant перед обновлением состояния.

## 5. WebSocket
1. Адрес из `NEXT_PUBLIC_WS_URL`, маршрут `/ws/rooms/{code}/`; автоматический выбор `ws`/ `wss` по переменной окружения.
2. Первое сообщение строго `{"type":"auth","token":"..."}`. Не передавать token в query string или console.
3. Обработать `auth.ok`, `room.snapshot`, `game.started`, `game.snapshot`, `player.moved`, `player.died`, `body.spawned`, `task.progress`, `meeting.started`, `vote.updated`, `meeting.ended`, `game.ended`, `pong`, `error`.
4. Reconnect с backoff 0.5/1/2/4/8 секунд + небольшая случайная задержка; при 4401 показать re-auth, не делать бесконечных попыток; не копить несколько одновременных сокетов.
5. При reconnect ждать авторизации и полноценного server snapshot; не «воскрешать» клиента из старой памяти.
6. Ping раз в 10 секунд, визуально отмечать `connecting/connected/reconnecting/offline`.
7. Если игрок обновил страницу, WS повторно связывается с гостевой сессией и получает актуальный state.
8. Все события типизировать discriminated unions. Указать payloads в отдельном документе при согласовании с Илияр.

## 6. Задания экипажа
Сделать 3 простые оригинальные мини-игры:
- `wire-link`: соединить 3 пары разъёмов;
- `sequence`: нажать 4 подсвеченные панели в нужной последовательности;
- `upload`: удерживать действие пока завершится progress bar.
Сервер назначает каждому члену экипажа 3 task_id с местоположением; мини-игра отображается только при взаимодействии рядом с точкой. После локального прохождения отправить `task.complete` и дождаться серверного `task.progress`. Дубликат завершения не увеличивает прогресс. Предатель может имитировать, но не повышать общий task прогресс.

## 7. Предатель, смерть, собрание
- Кнопка Kill появляется только для своей роли impostor и живого персонажа, сервер контролирует дистанцию, 25s cooldown, phase и цель.
- Убитый игрок получает визуальный dead/spectator state, управление и возможность задач/голосов — по правилам сервера; мёртвые не должны иметь возможность действовать.
- Кнопка Report только рядом с body и если жив; Emergency отдельно с ограничением 1 на игрока.
- Meeting: discussion 30s, vote 30s; одна попытка голоса на раунд, можно skip; после отправки подсветить выбор и блокировать повтор.
- При tie/skip нет изгнания; после `meeting.ended` возвращаемся на карту. Не раскрывать роли живых игроков.
- Финал только после `game.ended`, ни одной самодельной проверки victory на фронте.

## 8. Качество, безопасность и производительность
- Desktop 1366×768, mobile 390×844; responsive HUD без перекрытия кнопок и визуального чата (чат не обязателен в MVP).
- Нагрузка: 10 игроков, до 10Hz snapshot; без бесконечно растущих массивов и утечек событий.
- На слабом устройстве допустимо снижение декоративной анимации, но ввод и игровой state остаются отзывчивыми.
- Все данные сокета считаются untrusted для UI; текст никнеймов — обычный escaped React text, никогда raw HTML.
- Не помещать скрытые роли/задачи остальных игроков в клиентское состояние; backend не должен отправлять их.
- Поддержка `prefers-reduced-motion`, keyboard controls, focus на meeting dialogs.

## 9. Проверки / definition of done
1. 2–4 браузерных окна видят движение других пользователей в пределах ~100–250ms на localhost.
2. WASD/стрелки, диагональ и mobile controls корректны.
3. Переподключение восстанавливает authoritative positions/phase, без дублирования WebSocket listeners.
4. Три мини-игры работают и увеличивают прогресс только по server ack.
5. Видимость Kill/Report/Emergency зависит от role/phase/range; при backend rejection UI восстанавливается.
6. Встреча, таймер, skip/tie, итог голосования, возврат к map отображаются.
7. Dead spectator и finish screen работают.
8. TypeScript, ESLint, production build проходят; проверить сеть/отключения и 10 участников.
9. PR содержит видео геймплея, screenshots desktop/mobile и список проверенных WebSocket событий.

**Этапы:** A — карта/HUD и мок визуализации в памяти; B — реальный WS/snapshot/movement; C — задачи, предатель, meeting/voting/win UI и тесты. Моки обязательно убрать из production после интеграции. Зависимость: Ильяр поставляет схемы событий, Ибро — guest token и маршрут лобби.
